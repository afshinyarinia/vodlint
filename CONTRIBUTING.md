# Contributing to VoDLint

Start with a minimal playlist or segment fixture showing a user-visible
problem. Contributions should preserve predictable exit codes, deterministic
JSON, partial results, and the lightweight runtime dependencies.

## Setup

Python 3.11 or newer:

```bash
git clone https://github.com/afshinyarinia/vodlint.git
cd vodlint
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# PowerShell:
# .venv\Scripts\Activate.ps1
python -m pip install -e '.[dev]'
```

Run the required checks:

```bash
python -m ruff check .
python -m black --check .
python -m pytest --cov=vodlint --cov-branch --cov-report=term-missing --cov-fail-under=85
python -m build
python -m twine check dist/*
python tools/check_distribution.py
```

The distribution checker expects one wheel in a fresh `dist/` and creates a
temporary environment. It installs the wheel and exercises valid, invalid, and
missing inputs outside the checkout. It needs access to the dependency index.
Ordinary tests use generated bytes and local HTTP servers; they need no network
service or public streaming URLs.

## Adding a check or fixing a defect

1. Open an issue with the version, OS, expected behavior, and a small reproduction.
2. Add a failing regression test that exercises the actual analyzer or CLI.
3. Implement the smallest correction; do not weaken assertions to make it pass.
4. For a new rule, specify its ID, severity, applicability, and remediation.
5. Add valid and invalid fixtures and document the rule and limitations.
6. Run the full suite, lint, formatting and relevant distribution checks.
7. Describe the resulting behavior and test evidence in the pull request.

Do not share signed URLs, authentication headers, private media, or keys in public
reports. Use synthetic fixtures or media whose redistribution rights are clear.

## Architecture and compatibility

- `network.py`: local/HTTP loading, shared session, retry/timeout policy, ranges and budgets.
- `rules.py`: manifest parsing and pure rule evaluation.
- `models.py`: findings, redaction, versioned report and verdict.
- `analyzer.py`: configuration, traversal, metadata and sample orchestration.
- `cli.py`: CLI/env precedence, formatting and process exit codes.
- `parsers/sniff.py`: conservative container signatures, not media decoding.

Preserve schema-v1 field types. New optional fields/rules are allowed; removals
and type changes require a new schema version. Always distinguish declared
metadata, observed bytes, uninspected content, and resource failures.

## Test expectations

Tests should fail for a real behavioral regression, not implementation
reorganization. Use local HTTP fixtures for retries, redirects, cookies,
ranges, failures and timeouts. Test absolute and relative paths, Windows path
handling, JSON on failure, and installed entry-point status codes.

CI checks Python 3.11–3.14 on Windows and Linux, plus the minimum supported
runtime dependencies on Python 3.11. Distribution smoke checks run on both
operating systems. CI results must be reviewed before merging; adding a workflow
does not mean its hosted jobs have already passed.

Be respectful and constructive. Keep pull requests focused and explain any
compatibility changes in the changelog.
